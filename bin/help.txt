lp-audit: speed and code check for our landing pages

It tests a page the way an ad visitor sees it, checks the code before launch,
and writes a short report in simple English: what is wrong, how to fix it,
how to check the fix. Rules decide what is broken; AI only writes the summary.

USE IT IN THIS ORDER FOR EVERY LANDING PAGE

  Before launch (one command)
    lp-audit launch <page url> --code <site folder>
       Code check + speed test + form and tracking test. Ends with READY or NOT READY.
       Run the Claude command printed at the end of the code report (one pass per site).
       Fix the problems and run it again until it says READY.
       Do the last run on the real domain (the Cloudflare cache check only works there).

  While ads are running (a few days after start, then every week)
    lp-audit live <page url>         same tests + real visitors' data
    lp-audit weekly <page url>       Windows: runs it every Monday, a window opens only if visitors got slower

  Once a month
    lp-audit learn                   turn Claude's review findings into new rules

COMMANDS

  lp-audit launch <url> --code <folder>
                                   code check, then prelaunch. READY / NOT READY at the end.
                                   GTmetrix is skipped while the code has must-fix problems.

  lp-audit prelaunch <url>         before launch: lab test x3 (phone + desktop), real-visitor test
                                   (waits, scrolls, finds what jumps, phone screenshots), form and
                                   tracking test, Google Ads basics, server checks, GTmetrix x1
       --runs 1                    faster (1 run instead of 3)
       --no-gtmetrix               skip GTmetrix (free plan has only 5 tests)
       --gtmetrix-url <link>       GTmetrix auto-login failed? Run it by hand on gtmetrix.com and
                                   paste the report link here (uses no test)
       --local-lab                 use this laptop for the lab test (for staging Google cannot open)
       --submit                    really send the form (test lead "LP Audit Test"). Staging only,
                                   or tell sales to ignore it. Without it the form is NOT sent.
       --thank-you <url>           also open the thank-you page and check the Ads conversion fires

  lp-audit live <url>              ads running: same tests + Google and Cloudflare real-user data
       --gtmetrix                  also run GTmetrix once

  lp-audit watch <url>             the weekly check: live test, warns only when Cloudflare's 7-day
                                   data got worse (over target and 20% worse than last time)
  lp-audit weekly <url>            Windows: run "watch" every Monday 11:00 (Task Scheduler)
  lp-audit weekly <url> --stop     stop it

  lp-audit code [folder]           code audit of a site folder (default: the folder you are in)
       --url <page url>            link speed problems to code lines, check what is uploaded
       --no-semgrep                skip Semgrep (it needs internet)
                                   False alarm on a line? Add the comment  lp-audit: ok  on that
                                   line (// lp-audit: ok  or  # lp-audit: ok  or  <!-- lp-audit: ok -->)

  lp-audit learn                   monthly: review Claude's findings, add good ones as rules.
                                   Then commit and push code_rules.json so the team gets them.
  lp-audit rules                   list rules: how often each fired or was silenced

  lp-audit accept <url> <id> --why "reason"
                                   keep one problem on purpose on that page (e.g. sales needs the
                                   chat widget). It stays listed under "Accepted, not fixed" in every
                                   report but no longer makes it NOT READY. The id is shown next to
                                   each problem. Then commit and push accepted.json for the team.
  lp-audit accept <url>            list what is accepted on that page
  lp-audit accept <url> <id> --remove
                                   count it again

  lp-audit history <domain>        past audits of a site (each page separately)
  lp-audit clean <domain>          delete a site's reports
  lp-audit clean --older-than 90   delete reports older than 90 days
  lp-audit open                    open the reports folder
  lp-audit share                   open the folder for the team chat (PageSpeed and GTmetrix
                                   screenshots + a short summary, one dated folder per audit)

  lp-audit setup                   first time: create .env, check Docker and Ollama, build
  lp-audit update                  get the latest version (git pull + rebuild)
  lp-audit test                    self-check, prints "demo ok"
  lp-audit help                    this text

Reports: reports/<domain>/<date>_<mode>/report.md inside the lp-audit folder.
For the team chat: reports/share/<date> <site> <page> <mode>/ (post these, not the report).
Something went wrong? The tool says so in red-ish "!!!" lines and saves a file in
reports/errors/. Send that file to Shehzar. It never contains your keys or passwords.
Every command also has its own help, e.g.: lp-audit prelaunch --help
